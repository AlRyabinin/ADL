# ADL Device Emulator

Отдельное Windows-приложение для сетевой эмуляции нескольких устройств ADLPDS. Проект рассчитан на .NET 8 WinForms и не требует подключения к основной БД ADL.

## Что реализовано

- Периодическая рассылка `COMMAND_STATUS` (1 раз в секунду) на заданный IPv4-адрес и UDP-порт.
- Обработка `COMMAND_GET_STATUS` с немедленной отправкой статуса отправителю.
- Обработка `COMMAND_GET_PARAM` и `COMMAND_SET_PARAM` с ответом, `TID` и флагом RESPONSE.
- Формат заголовка ADLPDS на 12 байт, CRC16 и кодирование `ParamDataId` / `ParamDataValue` по исходникам проекта `ADL(4).zip`.
- Параметры UUID, Block, Name, IP, Mask, Gateway, MAC (необязательный), каналов и потоков в минимальном объёме для чтения конфигуратора.
- Multicast transport, собственный multicast-адрес и все 32 `IgmpAddress`.
- Сохранение состояния виртуальных устройств в `devices.json`.
- Несколько экземпляров устройств одновременно: каждому назначается свой UDP-порт-источник, чтобы конфигуратор различал устройства по `IPEndPoint`.

## Профили в демонстрационном наборе

- `IKB` — исполнительное устройство.
- `PU` — цветное ПУ.
- `PU24` — чёрно-белое ПУ.
- `INDIGATE` — гейт.

Устройства имеют пересекающиеся индексы каналов, чтобы проверять логику автоматических multicast-подписок. UUID генерируются при создании демонстрационного набора и сохраняются в JSON после первого сохранения.

## Редактирование форм в Visual Studio

Обе формы вынесены в стандартные WinForms Designer-файлы:

- `MainForm.cs` + `MainForm.Designer.cs` — главное окно, список устройств, панель управления и журнал.
- `DeviceEditorForm.cs` + `DeviceEditorForm.Designer.cs` — форма создания/изменения виртуального устройства.

Открой решение в Visual Studio 2022, в обозревателе решений выбери `MainForm.cs` или `DeviceEditorForm.cs` и нажми **Просмотреть конструктор** (View Designer). Расположение, размеры, подписи, колонки таблицы и свойства контролов меняются визуально. В файлах `.cs` остаётся прикладная логика и обработчики событий; вручную UI там не создаётся.

У `DeviceEditorForm` оставлен пустой конструктор без параметров для Visual Studio Designer. Рабочий конструктор с параметрами используется приложением во время создания/редактирования профиля.

## Запуск

Требуется Windows и .NET 8 SDK (для сборки) или Visual Studio 2022 с компонентом разработки .NET Desktop.

Из папки проекта:

```powershell
dotnet run
```

Либо открой `ADLDeviceEmulator.csproj` в Visual Studio и запусти проект.

## Настройка сети

1. В конфигураторе ADLPDS выбери тот же сетевой интерфейс, который выбран в эмуляторе.
2. В эмуляторе выбери локальный IPv4 этого интерфейса.
3. По умолчанию `STATUS` отправляется на `255.255.255.255:20000`. Если широковещательные пакеты в сети фильтруются, укажи конкретный IPv4 компьютера с конфигуратором и порт `20000`.
4. У каждого виртуального устройства должен быть уникальный UDP-порт (демо: `21001`–`21004`). Конфигуратор отправляет `GET_PARAM` / `SET_PARAM` на endpoint, с которого получил статус, поэтому эти порты используются и для обратного обмена.
5. При необходимости разреши UDP-трафик для выбранных портов в Windows Defender Firewall.
6. Нажми «Запустить устройства». В журнале появятся `START`, `GET_PARAM` и `SET_PARAM`.

Если эмулятор и конфигуратор работают на одном ПК, выбери в обоих приложениях один и тот же реальный Ethernet/Wi-Fi интерфейс. Если тестируешь только через loopback, выбери `127.0.0.1` и укажи его как адрес назначения STATUS.

## Управление виртуальными устройствами

В главном окне есть список виртуальных устройств и отдельные команды управления:

- **Создать устройство** — открывает форму, где задаются ADLPDS-тип, имя, UUID, блок, UDP-порт, сетевые параметры, MAC (необязательно), индексы каналов и multicast-настройки.
- **Изменить** или двойной щелчок по строке — открыть профиль выбранного устройства. Если оно запущено, эмулятор перезапустит только его; остальные устройства продолжат работать.
- **Удалить** — остановить выбранное устройство, если оно запущено, и убрать его из списка после подтверждения.
- **Запустить выбранное / Остановить выбранное** — управлять одним устройством.
- **Запустить все / Остановить все** — управлять всеми включёнными профилями.

Создание, редактирование и удаление доступны, пока остальные виртуальные устройства работают. Новое включённое устройство запускается сразу. Удаление одного устройства не останавливает остальные. Для каждого профиля требуется уникальный UDP-порт; пара UUID + Block также должна быть уникальной.

Изменения профилей и значения, принятые через `SET_PARAM`, сохраняются в `devices.json` рядом с приложением. Кнопки «Загрузить» и «Демо-набор» заменяют список целиком и поэтому доступны только после остановки работающих устройств.

Поля профиля: `Type` (до 8 символов), UUID, `Block`, порт, IP, маска, шлюз, необязательный MAC, `ChannelIndexes`, `Transport`, `OwnAddress`, до 32 `Subscriptions`.

## Границы первой версии

Это **сетевой эмулятор протокола конфигуратора**, а не запуск машинного кода из `adl006_color.hex` / `ADL006_bw.hex` и не эмулятор аппаратуры микроконтроллера.

Поддержаны обнаружение и обмен параметрами, необходимые для проверки списка устройств, чтения/записи сетевых параметров и мультикаста. Не реализованы полноценные firmware upgrade/detect, backup, потоковые каналы, переключение каналов в реальном времени и все аппаратные функции прошивки. Эти команды не следует считать протестированными на этой версии.

Формат и поля ADLPDS взяты из `AdlpdsService.cs`, `Core/Packet/*`, `Core/Core.cs` и `LiveConfig/LiveConfigCodec.cs` из предоставленного архива `ADL(4).zip`. Совместимость проверена статически по исходникам; в среде создания архива .NET SDK отсутствовал, поэтому сборка и сетевой прогон на реальном конфигураторе здесь не выполнялись.
