# ADL — аудит перед выпуском заказчику

Дата аудита: 18.11.2026  
Источник: загруженный проект `ADL(1).zip`.

## Результат

**Сейчас проект нельзя честно обозначить как проверенный готовый релиз.** В архиве есть исходники приложения и конфигуратора БД, но в текущем окружении отсутствует .NET SDK и Windows-среда, поэтому компиляция и запуск не выполнялись. Кроме того, в исходниках обнаружены незавершённые функции, которые обсуждались как необходимые перед передачей.

## Найденные блокирующие пункты

1. `AdlpdsConfig/fMain.cs`, `miSaveConfigurationToDb_Click`: после закрытия `fConfSaver` метод вызывает `_repo.SaveAsync(config)`. В нём нет отправки собранных параметров на физическое устройство (записи IP/маски/шлюза, SID, UUID и основной конфигурации). Следовательно, сценарий «одни и те же параметры в БД и на устройство» в переданном архиве ещё не реализован.
2. `AdlpdsConfig/Controls/fDeviceIdentityDialog.cs`, `button1_Click_1`: обработчик пустой. Генерация UUID по SN и `DeviceType` не реализована; получение `DeviceType` из БД в этом диалоге отсутствует.
3. `AdlpdsConfig/fMain.cs`, `BuildPUConfig`: метод принимает только `PuColorConfigDto`, поэтому общей подготовки конфигураций всех вариантов PU для отправки в текущем виде нет.
4. В решении нет отдельного тестового проекта. Проверку протокольной записи, БД и реальных устройств необходимо выполнить на Windows-машине с доступом к оборудованию.

## Что подготовлено

- Скрипт `Build-Release-Win10-x64.ps1` для публикации основного приложения и конфигуратора БД как self-contained `win-x64`.
- Инструкция по сборке и первому запуску `RELEASE-INSTRUCTIONS-RU.md`.
- Поставка рассчитана на папку с файлами, не на установщик и не на single-file EXE.

## Что остаётся сделать до передачи

1. Завершить два функциональных пункта выше и проверить их на реальном устройстве.
2. Запустить PowerShell-скрипт на Windows 10/11 x64 с .NET 8 SDK и доступом к NuGet.
3. Исправить все ошибки сборки, если они появятся.
4. Проверить результат на чистой Windows 10 x64 без установленного .NET Runtime.
5. Провести функциональную приёмку по чек-листу в `RELEASE-INSTRUCTIONS-RU.md`.

До выполнения этих пунктов папка сборки является подготовкой к релизу, но не подтверждённой клиентской поставкой.
