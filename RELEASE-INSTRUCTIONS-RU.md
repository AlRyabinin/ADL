# ADL — подготовка поставки для Windows 10 x64

## Состав поставки

Скрипт `Build-Release-Win10-x64.ps1` формирует папку `release\ADL-Win10-x64`:

- `Application\` — основное приложение ADLPDS Configurator;
- `DatabaseSetup\` — утилита настройки подключения к базе данных;
- `README.txt` — краткая памятка для передачи.

Поставка self-contained для `win-x64`: .NET 8 Desktop Runtime на компьютере заказчика не нужен. Это папка с файлами, не установщик и не один EXE.

## Требования к машине разработчика

- Windows 10/11 x64;
- .NET 8 SDK (именно SDK, не только Runtime);
- доступ к NuGet для восстановления пакетов.

## Сборка

Из корня исходного проекта откройте PowerShell и выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Build-Release-Win10-x64.ps1
```

Можно указать другой каталог:

```powershell
.\Build-Release-Win10-x64.ps1 -OutputDirectory 'C:\Build\ADL-Win10-x64'
```

Скрипт сначала восстанавливает пакеты решения, затем публикует основное приложение и конфигуратор БД в Release для `win-x64` с включённым .NET runtime. Эмулятор устройств в клиентскую поставку не включается.

## Первый запуск у заказчика

1. Распаковать всю папку поставки в постоянный каталог, например `C:\ADL`.
2. Запустить `DatabaseSetup\AdlpDBConfigurator.exe`.
3. Выбрать SQLite или MySQL, заполнить параметры подключения и сохранить настройки.
4. Для MySQL заранее создать БД/пользователя с необходимыми правами и обеспечить сетевой доступ к серверу. Не использовать `root` в рабочей эксплуатации.
5. Запустить `Application\AdlpdsConfig.exe`.
6. При первом запуске выбрать сетевой интерфейс, через который приложение обнаруживает устройства.
7. Проверить подключение к БД и обнаружение тестового устройства.

Файл подключения хранится в `%ProgramData%\ADL\Adlp\Configuration.json`. Для SQLite путь к `data.db` по умолчанию также находится в этом каталоге. Поэтому настройки и база не теряются при замене папки приложения.

## Передача заказчику

- Передавать содержимое всей папки `ADL-Win10-x64`, а не только `AdlpdsConfig.exe`.
- Не включать в архив разработческие файлы `.git`, `obj`, `bin`, `.vs`, локальные `.csproj.user`, резервные копии и реальные пароли.
- Не копировать в поставку конфигурацию разработчика `Configuration.json` с учётными данными.
- Если требуются прошивки, положить согласованный комплект файлов в `Application\firmware\` после отдельной проверки.
- Если заказчику нужна готовая конфигурация сети, согласовать `network.conf` отдельно. При отсутствии файла приложение предлагает выбрать сетевой интерфейс.

## Обязательная проверка перед передачей

Сборка сама по себе не подтверждает работу с реальными устройствами. На чистой Windows 10 x64 проверить:

1. Запуск приложения и конфигуратора БД без установленного .NET Runtime.
2. Сохранение и повторное чтение настроек подключения.
3. Подключение к выбранной SQLite/MySQL базе.
4. Обнаружение устройств на нужном сетевом интерфейсе.
5. Чтение конфигурации каждого поддерживаемого типа устройства.
6. Запись тестовой конфигурации и повторное чтение с устройства.
7. Сохранение и повторную загрузку конфигурации из БД.
8. Мультикаст, резервное копирование и обновление прошивки — если эти функции входят в договорённый объём поставки.

Релиз считается принятым только после успешной проверки пунктов, относящихся к поставке, на реальном стенде заказчика.
